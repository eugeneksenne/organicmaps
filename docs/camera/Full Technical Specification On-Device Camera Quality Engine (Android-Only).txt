Full Technical Specification: On-Device Camera Quality Engine (Android-Only)

Version: 6.0 — Flagship Production Grade

Target: Android 12+ (optimized for Android 16+)

Goal: A flagship-grade computational photography engine for nightlife that rivals Google Pixel, Samsung Galaxy, and Apple iPhone camera systems.

Hard Constraints:  
- 100% on-device. Zero cloud inference. Zero image telemetry.  
- Total on-device model footprint ≤ 105 MB.  
- Single-image latency: FAST < 800 ms, BALANCED < 4 s, MAXIMUM < 10 s on Snapdragon 8 Gen 3 equivalent.  

---

1. High-Level Objectives

- Build a complete imaging stack from sensor RAW through JPEG/Ultra HDR output.
- Implement a zero-copy GPU-native pipeline using `AHardwareBuffer`, Vulkan compute, and GPU textures to eliminate bitmap churn and GC pressure.
- Use a plugin-based AI execution graph with dependency resolution, memory pooling, and stage-level sandboxing.
- Capture and fuse multiple RAW frames with hybrid HDR reconstruction before any AI enhancement.
- Insert a dedicated AI ISP layer for RAW demosaic, denoise, and color correction.
- Maintain per-lens tuning profiles with full calibration, distortion, vignette, and color profiles.
- Operate via a formal camera state machine with clear lifecycle boundaries.
- Support Android Ultra HDR (JPEG_R) with SDR fallback and full Display P3 color management.
- Protect quality via AI confidence thresholds, per-stage quality evaluation, and automatic rollback.
- Learn per-device behavior via a split learning database without ever uploading images.
- Architect for future video pipeline (temporal denoising, AI Live, night video) without redesign.

3. Camera State Machine

Production cameras require explicit state management.

```
[IDLE] ──open()──> [PREVIEW]
                      │
                      ▼
              [PRECAPTURE] ──meter/focus──> [PRECAPTURE_READY]
                      │                           │
                      ▼                           ▼
              [CAPTURE] <───────────────── [PRECAPTURE_READY]
                      │
                      ▼
              [PROCESSING] ──cancel──> [READY]
                      │
                      ▼
              [POSTPROCESS]
                      │
                      ▼
              [SAVING]
                      │
                      ▼
                  [READY]
```

Transitions:
- `PREVIEW` → `PRECAPTURE`: User half-presses shutter; engine begins metering, AF, and scene pre-analysis.
- `PRECAPTURE` → `PRECAPTURE_READY`: AE/AF locked, burst parameters computed.
- `PRECAPTURE_READY` → `CAPTURE`: Full shutter press; raw burst begins.
- `CAPTURE` → `PROCESSING`: Frames captured; HDR fusion and AI pipeline execute.
- `PROCESSING` → `READY`: Cancelled by user.
- `SAVING` → `READY`: File written, resources released.

Rules:
- Only one `CAPTURE` or `PROCESSING` session may exist at a time.
- `PREVIEW` pipeline runs concurrently and independently on a separate thread pool.
- On `READY`, return all memory pool objects and trigger `onTrimMemory()` if thermal pressure exists.

4. Zero-Copy Image Pipeline

Eliminate all `Bitmap` ↔ `Tensor` copies. Use GPU-native buffers throughout.

```
Camera2 ImageReader (RAW10/YUV)
        │
        ▼
AHardwareBuffer (GPU importable)
        │
        ▼
Vulkan Compute Image / GPU Texture
        │
        ├──► OpenCV GPU (alignment, optical flow)
        │
        ├──► LiteRT GPU Delegate (AI inference)
        │
        ├──► Vulkan Compute (HDR merge, tone map, blending)
        │
        ▼
HardwareBuffer Encoder (JPEG / JPEG_R)
        │
        ▼
Output File / Surface
```

Buffer Contracts:
- All intermediate stages read/write `AHardwareBuffer` with `VK_FORMAT_R16G16B16A16_SFLOAT` or `VK_FORMAT_R8G8B8A8_UNORM`.
- CPU access only for: EXIF writing, final file I/O, and LiteRT CPU fallback.
- Memory Pools: Reuse `AHardwareBuffer` instances across sessions:
  - `FramePool`: 16 buffers for burst frames.
  - `TensorPool`: 8 buffers for model I/O.
  - `TilePool`: 32 buffers for SR tiling.
  - `GpuBufferPool`: 12 buffers for Vulkan compute intermediates.

Fallback: If Vulkan is unavailable (Android 12 device without Vulkan 1.1), fall back to `OpenGL ES 3.1` compute shaders + `ImageReader`/`Allocation`. If GLES unavailable, fall back to `RenderScript` (deprecated but functional) → finally `Bitmap` CPU path.

7. Processing Pipeline (All Stages)

Pipeline must be interruptible at every stage. Check `isCancelled()` before and after each stage.

Stage -3: Camera Calibration
- Profile contents:
  - Intrinsic matrix (fx, fy, cx, cy)
  - Distortion coefficients (k1, k2, p1, p2, k3)
  - Sensor black level / white level per ISO
  - Color Correction Matrix (RAW → XYZ → Linear P3)
  - Lens shading map (LSC)
  - ISO-dependent noise profile (σᵣ read noise, σₛ shot noise scaling)
- Source: Pre-built per-device-family database (2–5 MB, downloaded on first run) + runtime estimation.
- Output: `CameraCalibrationProfile` passed to all downstream stages.

Stage -2: Multi-Frame Capture
- Capture 3–15 RAW10/RAW12 frames via Camera2 burst negotiated by `CameraFeatureNegotiator`.
- Exposure bracketing (±1 EV) if `CONTROL_AE_MODE_OFF` supported.
- Collect per-frame metadata: ISO, exposure time, focal distance, lens position, OIS state, timestamp.

Stage -1: Sensor Fusion & Pre-Analysis
- Sensor Fusion: Fuse gyroscope (200 Hz), accelerometer, OIS position, lens position, exposure metadata into per-frame `SensorPose`.
- AF Quality Analysis: Laplacian variance + edge magnitude. Classify: `SHARP` / `SOFT` / `OUT_OF_FOCUS`. If out of focus, disable aggressive sharpening later.
- Lighting Estimation: Classify illuminant (Ambient, Spotlight, LED, Laser, Neon, Flash, Mixed) + estimate CCT/tint.
- Reflection & Flare Detection: Lightweight CNN (2 MB INT8) or algorithmic anisotropic highlight analysis. Output artifact mask.

Stage 0: Motion Analysis & Hybrid HDR Fusion
- Motion Analysis: Sensor-fused pose + optical flow (OpenCV GPU). Compute:
  - `cameraMotionScore`, `faceMotionScore`, `sceneMotionScore`
- Adaptive HDR Strategy:
  
Motion Level	Strategy	
Low (< 2 px)	Full hybrid HDR: RAW merge → linear RAW → local HDR reconstruction	
Medium (2–8 px)	Motion-compensated HDR: block-wise alignment + ghost rejection	
High (8–20 px)	Best-frame selection + AI enhancement	
Extreme (> 20 px)	Single frame, skip fusion	

- Hybrid HDR Reconstruction (replaces Mertens):
  1. Align all frames using homography + optical flow.
  2. Merge aligned RAW frames into linear RAW (exposure-weighted average for shadows, highlight reconstruction for clipped regions).
  3. Local HDR reconstruction: recover highlights using unclipped frames; lift shadows using longer exposures.
  4. Output: single high-bit-depth linear image.
- Lens Correction: Vignetting (LSC), chromatic aberration, dead pixel correction applied to merged result.

Stage 1: AI ISP (RAW → RGB)
New dedicated stage. Process linear RAW before RGB enhancement.

- Demosaic: Algorithmic (Malvar-He-Cutler) or AI-assisted demosaic if model available.
- AI ISP Model: Lightweight UNet (4 MB, INT8) operating on Bayer RAW.
  - CFA reconstruction
  - RAW denoise (frequency-aware: chroma aggressive, luma gentle)
  - Dead pixel interpolation
  - Initial color correction (CCM application)
- Output: Linear RGB float32 image in scene-referred space.

Stage 2: Scene Classification
- Model: MobileNetV3-Small, INT8. Size: 2 MB.
- Classes: Club Dance Floor, DJ Booth, VIP Lounge, Bar Counter, Live Band, Festival Stage, Crowd Selfie, Flash Selfie, Bottle Service, Sparklers, LED Wall, Fire Effects, Street Night, Restaurant, Portrait, Group Photo, Indoor, Outdoor.
- Confidence threshold: If top class < 0.65, label `UNKNOWN`, use conservative `Portrait` tuning.

Stage 3: Semantic Segmentation + Portrait Matte
- Model: DeepLabV3+ MobileNetV3, INT8. Size: 5 MB.
- Classes: Background, Sky, Wall, Floor, Person, Face, Hair, Eyes, Skin, Clothing, Glass, Bottle/Drink, Food, Neon Light, Smoke, Stage/DJ Equipment.
- Portrait Matte: Additional alpha head for soft subject isolation.
- Confidence fallback: If mean confidence < 0.6, use bounding-box masks from face detection.

Stage 4: Object Detection
- Model: YOLO-Nano, INT8. Size: 3.5 MB. Lazy-loaded.
- Classes: Glasses, Drinks, Bottles, Food, DJ Equipment, Microphones, Phones, Fireworks.
- Threshold: Confidence > 0.6 only.

Stage 5: Face Detection & Landmarking
- Model: BlazeFace, FP16. Size: 1 MB.
- Output: Bounding boxes + 468-point dense landmarks.
- Threshold: Confidence > 0.7.

Stage 6: AI White Balance, Exposure & Noise Model
- Sensor Noise Model: Look up σᵣ and σₛ from `CameraCalibrationProfile` by ISO. Compute per-pixel noise estimate σ² = σᵣ² + σₛ² · I.
- Adaptive White Balance: Per-region correction guided by segmentation + lighting:
  - Skin: preserve warmth, correct magenta/green only.
  - Neon/LED: preserve atmosphere.
  - Background: neutralize aggressively.
  - Flash: cool slightly.
- Local Exposure: Face lift + highlight recovery using HDR fused data.

Stage 7: End-to-End RGB Enhancement
- Model: Lightweight UNet or Mobile AI 2025 DaHua-IIG variant. Size: 12 MB, FP16.
- Inputs: RGB + segmentation mask + noise map + scene label + lighting profile.
- Purpose: Shadow recovery, tone mapping, color grading, artifact suppression.
- Skin Tone Protection: Hue locked within ±5° on skin mask.

Stage 8: Face Restoration
- Model: GFPGAN-lite or CodeFormer-mobile. Size: 8 MB, FP16. Lazy-loaded.
- Input: Aligned face crops (256×256).
- Blend: Feathered using segmentation mask + portrait matte alpha.

Stage 9: Selective Super-Resolution (Tile Scheduler)
- Model: Real-ESRGAN w8a8.
- Tile Scheduler:
  - Priority queue: face tiles → hair → eyes → clothing/jewelry → objects.
  - Skip smooth regions (skin, background, smoke).
  - Adapt tile size to free RAM:
    - 
> 2 GB free: 256×256 tiles
    - 1–2 GB: 128×128 tiles
    - < 1 GB: skip SR
- Tier selection:
  - FAST: Skip.
  - BALANCED: Real-ESRGAN-General-x4v3 (5 MB). 128→512.
  - MAXIMUM: Real-ESRGAN-x4plus (16.7 MB). 256→1024.
- Blending: Laplacian pyramid, 16 px feather.

Stage 10: Intelligent Sharpening
- Algorithmic (unsharp mask / deconvolution).
- If AF quality = `OUT_OF_FOCUS`: skip entirely.
- Sharpen: eyes, hair, jewelry, text, labels. Avoid: skin, smoke, bokeh, flare regions.

Stage 11: AI Quality Evaluation & Rollback
- Model: MobileNetV3 regressor, INT8. Size: 3 MB.
- Scores: blur, noise, exposure, color, faceSharpness, highlightClipping, overall (0–100).
- Rollback Logic:
  - If `enhanced.overall < original.overall * 0.92` → rollback to Stage 7 output.
  - If still worse → rollback to Stage 0 (hybrid HDR fused output).
  - Log reason to learning database.

Stage 12: Post-Processing & Encoding
Color Pipeline:

```
Linear Scene-Referred → XYZ (CCM) → Linear P3 → Display P3 → sRGB fallback + Ultra HDR Gain Map
```

1. Tone mapping to target color space (Display P3 or sRGB).
2. Ultra HDR (Android 14+): If supported, generate HDR gain map from linear data. Encode `JPEG_R` with SDR base + gain map. Fallback to standard JPEG on failure.
3. Beauty mode (optional):
   - NATURAL: skin smoothing (strength 0.2) on skin mask.
   - SOCIAL: skin + eye brightening + mild contour (strength 0.4).
   - Never alter bone structure.
4. Mild global sharpening (0.15).
5. Encode to JPEG/JPEG_R.
6. Preserve EXIF: orientation, timestamp, GPS, color profile, lens info, MakerNotes.

8. AI Execution Graph & Plugin System

Plugin Interface:

```kotlin
interface CameraStage {
    val stageId: String
    val modelDependencies: List<String>      // ModelRegistry IDs
    val inputDependencies: List<String>      // Stage IDs
    val isOptional: Boolean
    val priority: WorkPriority               // CRITICAL, HIGH, MEDIUM, BACKGROUND
    val sandbox: StageSandbox                // RAM, delegate, min Android, checksum
    
    suspend fun execute(ctx: PipelineContext): StageOutput
    fun confidenceThreshold(): Float = 0.5f
}

enum class WorkPriority { CRITICAL, HIGH, MEDIUM, BACKGROUND }
```

Execution Graph Builder:

```kotlin
val graph = ExecutionGraphBuilder()
    .addNode(SceneClassifierStage())
    .addNode(SegmentationStage().dependsOn("scene"))
    .addNode(LightingEstimationStage().dependsOn("scene"))
    .addNode(FaceDetectionStage())
    .addNode(ReflectionDetectionStage())
    .addNode(EnhancerStage().dependsOn("segment", "lighting", "face", "reflection"))
    .addNode(FaceRestoreStage().dependsOn("enhancer", "face"))
    .addNode(SuperResolutionStage().dependsOn("enhancer", "segment"))
    .build()
```

Scheduler resolves the DAG and executes independent branches concurrently.

9. Scheduler Architecture

Three schedulers cooperate:

Scheduler	Responsibility	
`PipelineScheduler`	Manages the overall capture-to-save state machine. Orchestrates stage execution via the AI Execution Graph.	
`WorkScheduler`	Priority-based thread pool (CRITICAL > HIGH > MEDIUM > BACKGROUND). CRITICAL work (HDR merge) gets dedicated threads; BACKGROUND work (telemetry, learning DB writes) runs on idle cores.	
`TileScheduler`	Manages SR tile queue. Prioritizes face tiles, skips low-detail tiles, adapts tile size to RAM.	

Concurrency Rules:
- `CRITICAL`: HDR merge, AI ISP — must complete before any downstream stage.
- `HIGH`: Scene, segmentation, face detection, lighting — can run in parallel after merge.
- `MEDIUM`: Object detection, reflection detection, quality evaluation.
- `BACKGROUND`: Learning DB update, telemetry flush, benchmark logging.

Zero-allocation policy: Reuse every buffer.

```kotlin
object MemoryPools {
    val framePool: FramePool        // AHardwareBuffer for burst frames
    val tensorPool: TensorPool      // LiteRT input/output tensors
    val gpuPool: GpuBufferPool      // Vulkan textures / compute buffers

```

Pool Rules:
- Acquire at `CAPTURE` start. Release at `READY`.
- If pool exhausted, allocate temporary buffer and log to health monitor.
- `onTrimMemory()` triggers aggressive pool compaction and lazy model unloading.

13. Advanced Thermal Manager

Graduated thermal response instead of single threshold.

State	SoC Temp	Actions	
NORMAL	< 42°C	Full pipeline, all tiers allowed.	
WARM	42–48°C	Reduce burst by 2 frames. Disable object detection.	
HOT	48–55°C	Force FAST tier. Disable SR and face restore. Single-frame capture.	
CRITICAL	55°C	Cancel active pipeline immediately. Return original frame. Unload all lazy models.	

Transitions: Hysteresis of 3°C to avoid oscillation.
