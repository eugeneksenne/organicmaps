# FOMO Metadata Engine (FME)

## Vision

The Metadata Engine is the nervous system of the FOMO Quantum Camera Engine.

Instead of every module performing its own AI analysis, the Metadata Engine continuously builds a complete understanding of every camera frame and publishes structured metadata that any processing module can consume.

This eliminates redundant computation, reduces latency, improves battery life, and ensures all camera features operate from a single, consistent understanding of the scene.

# Responsibilities

The Metadata Engine owns exactly six responsibilities.

## 1. Frame Synchronization

Every frame gets a unique ID.

```text
Frame 15820

↓

Face Metadata

↓

Scene Metadata

↓

Depth Metadata

↓

Segmentation Metadata
```

Everything references the same frame.

```kotlin
FrameMetadata.frameId = 15820
```

No guessing.

Instead:

| Model             | Frequency               |
| ----------------- | ----------------------- |
| Face              | Every frame (30–60 FPS) |
| Segmentation      | Every 2 frames          |
| Scene Recognition | Every 10–15 frames      |
| FastDepth         | Every 5 frames          |

# Hardware Acceleration Manager

Not every device has the same hardware.

Create a manager that automatically chooses the fastest backend.

```kotlin
enum class InferenceBackend {

    NPU,

    GPU,

    DSP,

    CPU

}
```

Priority

```text
NPU

↓

GPU

↓

DSP

↓

CPU
```

Examples:

* Qualcomm Snapdragon → Hexagon NPU
* Google Tensor → Edge TPU
* Samsung Exynos → Samsung NPU
* MediaTek Dimensity → APU
* Older devices → GPU or CPU

The selection should happen automatically at startup.

# Tier 1 Public API

Everything else in the camera talks to **one API**.

```kotlin
interface MetadataEngine {

    suspend fun start()

    suspend fun stop()

    fun latestFrame(): FrameMetadata?

    fun observeFrames(): Flow<FrameMetadata>

}
```

Notice that the rest of the app never calls MediaPipe, LiteRT, or ONNX directly. The Metadata Engine hides those implementation details.

## V1 vs. Future Versions

Build the Metadata Engine so it doesn't care **which model** produces the metadata. Today, `FacePipeline` might use MediaPipe Face Landmarker; in a future release you could swap it for a custom FOMO face model without changing any downstream modules. The same applies to scene recognition, segmentation, and depth estimation.

That separation is what allows companies like Google and Apple to improve camera quality every year while keeping the rest of their camera pipeline stable. It's also the foundation that will let your future **Tier 2** modules—SkinTone Guardian™, Motion Freeze AI™, Capture Intelligence™, and the Gold Standard processing pipeline—plug into the engine with minimal changes.
