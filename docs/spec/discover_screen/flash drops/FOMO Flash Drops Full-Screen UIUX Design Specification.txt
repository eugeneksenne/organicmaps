# FOMO Flash Drops Full-Screen UI/UX Design Specification

This is the **dedicated Flash Drops “See All” screen**, not the individual Flash Drop preview. It shows the complete active Flash Drop ecosystem around the user.

---

## 1. Screen purpose

The screen answers one question:

> **“What Flash Drops are happening around me right now?”**

It should prioritize **live, nearby, time-sensitive opportunities** while allowing the user to filter between:

**ALL · VENUE · EVENT · BRAND**

# 7. Countdown logic

The timer must be mathematically tied to the Flash Drop schedule.

If:

```text
Start: 20:00
End:   21:00
```

and current time is:

```text
19:30
```

show:

```text
STARTS IN

00:30:00
```

At:

```text
20:00
```

automatically change to:

```text
ENDS IN

01:00:00
```

At:

```text
20:30
```

show:

```text
ENDS IN

00:30:00
```

At:

```text
21:00
```

the Drop becomes inactive.

### Never use a manually entered countdown.

The timer is always derived from:

```text
starts_at
ends_at
current_time
```

# 12. Card dimensions

The Discover carousel uses:

**300dp × 200dp**

The See All screen is different.

Cards here should be **wide, compact list cards** optimized for vertical scrolling.

Recommended target:

**~150–165dp height**

with responsive width based on screen margins.

# 17. Address

The address is presented as a **single line** whenever the card width allows.

Example:

```text
📍 123 Open Street, Pretoria, 0003 · 250m away
```

This is a deliberate FOMO design rule.

The user should not need to open the Drop merely to discover where it is.

If the physical width is insufficient, the UI may visually truncate the line, while the full address remains available in the preview.

# 21. Interested, not claimed

FOMO Flash Drops **do not use claims**.

Therefore:

❌ `34 / 50 CLAIMED`

is not part of the Flash Drop UI.

Use:

✅ `34 interested`

The number represents actual user engagement with the Drop.

If there is no meaningful engagement count, simply omit it rather than fabricate social proof.

# 26. Ranking logic

The Flash Drops feed should prioritize genuine urgency.

A useful ranking hierarchy:

```text
ACTIVE NOW
    ↓
DISTANCE
    ↓
ENDING SOON
    ↓
JUST DROPPED
    ↓
ENGAGEMENT
    ↓
PERSONAL RELEVANCE
```

This prevents a highly engaged Drop several kilometers away from automatically outranking something happening 250m away in 10 minutes.

---

# 27. Expiration

When:

```text
current_time >= ends_at
```

the Drop leaves the active list.

No stale:

```text
00:00
```

cards should remain in Active Flash Drops.

If the user is already viewing the expired Drop in the full-screen preview, the UI can transition to an **Expired** state and then move them to the next active Drop.

---

# 28. Empty state

If there are no active Drops:

```text
⚡

NO FLASH DROPS RIGHT NOW

Nothing is happening nearby yet.

We'll let you know when something drops.

[ EXPLORE NEARBY ]
```

No expired content should be recycled simply to make the page look populated.

# 30. Final screen specification

### Header

**← · ⚡ FLASH DROPS · Filters**

### Filters

**ALL · VENUE · EVENT · BRAND**

### Dynamic hero

**Nearest relevant active Drop**

Contains:

* Status
* Hero image
* Title
* Source
* Full address
* Distance
* Actual schedule
* Actual offer
* Live countdown

### Active list

**ACTIVE FLASH DROPS · X LIVE**

Each card contains:

* Hero image
* Status
* Like
* Title
* Source
* Description
* Full address
* Distance
* Actual schedule
* Actual offer
* Live countdown
* Interested count
* Category

### Tap

Opens the **full-screen Flash Drop preview**.

### Core timing principle

**The schedule is the source of truth. The countdown is calculated from the schedule.**

### Core engagement principle

**Interested is the engagement signal. No fabricated claims or social proof.**

### Core location principle

**The user sees the actual address and proximity before opening the Drop.**

### Core hierarchy

**Discover carousel → See All → Full-Screen Preview → Action**

That gives Flash Drops a clean progression from **quick discovery → active exploration → immersive decision → action**, without making every screen carry every control.
