============================================================
PRIMARY OBJECTIVE
============================================================

Build the complete production-ready first-launch experience
from the supplied visual references and existing project
architecture.

The final experience must be:

- visually faithful to the supplied Findlyts references
- responsive
- accessible
- production-ready
- securely authenticated
- correctly connected to the user's Findlyts profile
- resilient to errors
- resilient to network failures
- resilient to process death
- resilient to session expiration
- free of fake authentication
- free of duplicate profile creation
- free of navigation loops
- free of inconsistent authentication states

Do NOT create mock authentication merely to make the UI appear
complete.

If a backend integration already exists, use it.

If authentication infrastructure exists, inspect it first and
extend it rather than replacing it unnecessarily.


============================================================
CRITICAL IMPLEMENTATION RULE
============================================================

Before changing code:

1. Inspect the existing project.
2. Inspect authentication implementation.
3. Inspect profile implementation.
4. Inspect navigation.
5. Inspect existing onboarding state.
6. Inspect database/schema models.
7. Inspect Supabase configuration if present.
8. Inspect existing repositories/services/use-cases.
9. Inspect existing UI components.
10. Identify duplicate implementations.

Do NOT immediately create new authentication, profile,
navigation, or state-management systems.

Reuse existing architecture where appropriate.

Do not create:

- duplicate onboarding state
- duplicate auth state
- duplicate profile state
- duplicate user tables
- duplicate navigation systems
- duplicate session managers

three introductory screens were displayed.

PART 19
IMPLEMENTATION LOOP
============================================================

Use the following loop for EVERY feature/state:

LOOP

1. DISCOVER
   Inspect existing implementation.

2. UNDERSTAND
   Determine current architecture and dependencies.

3. IMPLEMENT
   Build the missing behavior.

4. CONNECT
   Connect UI → state → backend → profile.

5. TEST
   Test happy path and failure paths.

6. VERIFY
   Compare UI against reference.

7. HARDEN
   Fix edge cases, race conditions and navigation issues.

8. RECHECK
   Confirm no existing functionality was broken.

9. DOCUMENT
   Record important implementation decisions.

10. MOVE ON
   Only after the current state is production-ready.
