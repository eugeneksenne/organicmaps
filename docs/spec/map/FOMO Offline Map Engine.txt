# FOMO Offline Map Engine

## Production Architecture Specification v6.0

**Status:** Production Architecture Specification
**Platform:** Android + iOS
**Architecture:** Kotlin Multiplatform + Native Organic Maps Core
**Map Data:** OpenStreetMap
**Core Map Engine:** Organic Maps
**Offline-first:** Yes
**Realtime:** Optional overlay
**Cloud dependency for core maps:** No

This specification evolves the uploaded FOMO Offline Map Engine architecture while preserving its central principle: **Organic Maps is the geographic foundation, while FOMO owns the nightlife, social, discovery, planning, and intelligence layers.** 

---

# 1. Vision

The FOMO Offline Map Engine is an **offline-first mapping platform built on Organic Maps and OpenStreetMap**.

Every FOMO user should be able to:

* View maps without internet
* Search downloaded regions
* Find venues
* Navigate offline
* Save places
* Plan nights
* View cached venue information
* Use GPS positioning
* Continue using core map functionality when FOMO's online services are unavailable

When connectivity is available, FOMO adds:

* Live venues
* Events
* Friends
* Live Moments
* Flash Drops
* Social activity
* Occupancy information
* Creator broadcasts
* AI recommendations
* Realtime updates

The map must never depend on the FOMO social or AI systems to remain functional.

---

# 2. Core Architectural Principle

> **Organic Maps is the geographic infrastructure of FOMO, not the business logic of FOMO.**

The architecture is:

```text
                    OpenStreetMap
                          │
                          ▼
                 Organic Maps Core
                          │
              ┌───────────┴───────────┐
              │                       │
              ▼                       ▼
       Offline Maps             Routing/Search
              │                       │
              └───────────┬───────────┘
                          ▼
                   FOMO Map Facade
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
       Venues           Social          Events
          │               │               │
          ▼               ▼               ▼
     FOMO Scores       Friends       Flash Drops
          │               │               │
          └───────────────┼───────────────┘
                          ▼
                    FOMO Map UI
```

FOMO must not place business logic directly inside Organic Maps.

Shared business logic belongs in `commonMain`.

```text
feature/maps/

commonMain/
├── FomoMapEngine
├── FomoMapState
├── FomoMapController
├── FomoLayerManager
├── FomoVenueEngine
├── FomoSearchController
├── FomoRoutingController
├── FomoOfflineMapsManager
├── FomoSyncEngine
├── FomoMapRepository

├── OrganicMapsAndroidBridge
├── OrganicMapsJNI
└── AndroidLocationProvider

iosMain/
├── OrganicMapsIOSBridge
├── OrganicMapsObjectiveCBridge
└── IOSLocationProvider
```

### Rule

`commonMain` must never depend on:

* Android `Context`
* Android `View`
* JNI implementation
* UIKit
* UIView
* Objective-C implementation details
* Platform-specific map rendering APIs

Platform-specific behavior belongs in platform adapters.

# 9. Organic Maps Upstream Strategy

FOMO should remain as close as practical to the upstream Organic Maps architecture.

### Do not:

```text
Modify Organic Maps
    ↓
Insert FOMO business logic everywhere
```

### Instead:

```text
Organic Maps
     +
FOMO Adapter
     +
FOMO Overlay System
```

This minimizes future maintenance and makes Organic Maps updates easier to integrate.

# 39. Add Location

```text

       ↓

       ↓
Validation
       ↓

       ↓

       ↓
```

# 40. OSM / External Place Data

```text

     ↓

     ↓

     ↓
```

```text
        ↓
Update FOMO layers
```

The map itself does not need to restart.

```text
      ↓

      ↓
```

No map reset should occur.

# 61. Production Rules

The following rules are mandatory.

### Rule 1

**Organic Maps owns geographic infrastructure.**

### Rule 2

**FOMO owns nightlife and social intelligence.**

### Rule 3

**FOMO business logic must not be embedded throughout Organic Maps.**

### Rule 4

**Offline map functionality must not depend on Supabase.**

### Rule 5

**Offline map functionality must not depend on AI.**

### Rule 6

**Realtime must be an overlay, never a requirement for the core map.**

### Rule 7

**Dynamic data must have freshness metadata.**

### Rule 8

**FOMO local data and Organic Maps map data remain logically separate.**

### Rule 9

**All offline mutations must enter the sync queue.**

### Rule 10

**All downloadable map packages must be verified before activation.**

### Rule 11

**The application must use one unified routing subsystem.**

### Rule 12

**Friend presence must use the existing FOMO presence/NightGuard system.**

### Rule 13

**External OSM/Overpass services must not be a fragile direct dependency of the mobile client.**

### Rule 14

**AI can improve discovery but can never become a dependency for map operation.**

### Rule 15

**Organic Maps should remain as close as practical to upstream.**

# 63. Final Vision

FOMO should not try to compete with Organic Maps at being a general-purpose offline geographic engine.

Instead:

> **Organic Maps gives FOMO the physical world. FOMO gives that world a nightlife pulse.**

The result is:

```text
OSM
 ↓
Organic Maps
 ↓
Offline geographic foundation
 ↓
FOMO Map Facade
 ↓
Venues + Events + Social + Plans
 ↓
Live + Flash Drops + Friends
 ↓
AI Discovery
 ↓
FOMO
```

The original specification already had the correct central idea: **OSM → Organic Maps → FOMO Offline Map Engine → FOMO Social Layer → AI Discovery Layer → FOMO Live Engine**. 

**v6.0 makes that architecture implementation-safe by explicitly separating geographic infrastructure, FOMO data, local offline state, synchronization, realtime layers, AI, native platform bridges, routing, downloads, security, and failure recovery.**
