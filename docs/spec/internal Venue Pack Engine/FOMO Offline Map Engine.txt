# FOMO Offline Map Engine

## Full Production Specification v5.2

**Foundation:** Organic Maps native C++ map engine + OpenStreetMap data
**FOMO role:** Venue intelligence, offline venue discovery, social map layers, events, realtime overlays, AI discovery and FOMO-specific map experience
**Platforms:** Android + iOS
**Architecture:** Kotlin Multiplatform shared logic + native Organic Maps engine bindings
**Organic Maps repository:** `D:\Android-fomo-main\engine`

This version consolidates the uploaded **FOMO Offline Map Engine**, the updated **FOMO Map Engine v5.1**, and the **MAP_AGENT_LOOP** architecture. The uploaded documents establish Organic Maps as the core offline mapping engine and FOMO as the layer above it.  

---

# 1. Mission

The FOMO Offline Map Engine is an **offline-first, venue-first map platform** built on Organic Maps and OpenStreetMap.

Its purpose is not to replace a generic navigation application.

Its purpose is:

> **Help users discover venues, decide where to go, plan their night and navigate there, whether they are online or offline.**

The map must remain useful without:

* mobile data
* Wi-Fi
* Supabase
* realtime services
* FOMO Live
* AI services

When connectivity returns, the map progressively reconnects to FOMO's social and realtime ecosystem.

The original Offline Map Engine establishes this offline-first principle explicitly.

# 4. Authoritative Venue Architecture

The Offline Map Engine **does not become the source of truth for venues**.

The hierarchy is:

```text
GLOBAL VENUE INTELLIGENCE
          │
          ▼
CANONICAL VENUE STORE
     SOURCE OF TRUTH
          │
          ▼
GLOBAL VENUE PACK CREATION
          │
          ▼
COUNTRY PACKS
          │
          ▼
DEVICE LOCAL VENUE STORE
          │
          ▼
FOMO MAP ENGINE
```

Country Packs are distribution snapshots.

The device is a replica.

Organic Maps' internal POI database is not the FOMO venue database.

The Country Pack architecture explicitly establishes this separation.

# 5. FOMO Venue Identity

Every permanent venue uses:

```text
FOMO Venue ID
```

Example:

```text
FMO-ZA-GP-JHB-00000127
```

The identifier:

> **Never changes.**

Provider IDs such as:

```text
OSM ID
Google Place ID
Foursquare ID
```

remain reference fields only.

The local map engine must always use:

```text
fomoVenueId
```

as the permanent venue reference.

# 76. Final Principle

The entire system can be summarized as:

```text
OSM
 ↓
ORGANIC MAPS
 ↓
FOMO OFFLINE MAP ENGINE
 ↓
FOMO VENUE INTELLIGENCE
 ↓
FOMO SOCIAL LAYERS
 ↓
FOMO AI
 ↓
FOMO LIVE
```

Or, more precisely:

> **Organic Maps provides the geographic world. Country Packs provide FOMO's permanent venue intelligence. The FOMO Offline Map Engine unifies those two systems into a single native offline map, while Events, Social, AI and Realtime add the living layer on top.**

This preserves the central rule from the uploaded architecture: **do not rebuild the mapping engine. Reuse Organic Maps' mature native capabilities and make FOMO the intelligence and experience layer above them.** 

And with your repository at `D:\Android-fomo-main\engine`, the implementation should treat that Organic Maps source as the **native map-engine foundation**, while the FOMO-specific KMP module remains the controlled interface between the rest of the application and that engine.
