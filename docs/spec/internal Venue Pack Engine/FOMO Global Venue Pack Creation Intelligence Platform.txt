# FOMO Global Venue Pack Creation Intelligence Platform

## Full Updated Production Specification v2.0

> **Purpose:** Build and continuously maintain FOMO's authoritative global venue intelligence system, then transform that intelligence into versioned, validated, offline-ready Country Packs consumed by the FOMO mobile application.
>
> **Core invariant:** The **FOMO Venue ID is permanent and never changes. Provider IDs are reference fields only.**

---

# 1. Platform Mission

The **FOMO Global Venue Pack Creation Intelligence Platform** is responsible for:

1. Discovering venues globally.
2. Scanning geographic regions systematically.
3. Acquiring venue information from supported sources.
4. Normalizing heterogeneous source data.
5. Resolving duplicate venues.
6. Assigning permanent FOMO Venue IDs.
7. Maintaining the canonical venue record.
8. Verifying venue information.
9. Classifying venues into FOMO categories.
10. Building geographic indexes.
11. Measuring venue completeness and coverage.
12. Generating Country Packs.
13. Generating category-specific packs.
14. Validating SQLite packs.
15. Versioning every pack.
16. Producing manifests and checksums.
17. Publishing full and delta updates.
18. Maintaining pack freshness.
19. Monitoring regional coverage.
20. Providing offline-ready venue intelligence to FOMO.

The platform is the **venue intelligence layer** of FOMO.

It does **not** replace Organic Maps.

---

# 2. System Ownership

The platform must maintain strict ownership boundaries.

```text
┌──────────────────────────┬──────────────────────────────────┐
│ SYSTEM                   │ RESPONSIBILITY                    │
├──────────────────────────┼──────────────────────────────────┤
│ OpenStreetMap            │ Geographic source data            │
│ Organic Maps             │ Offline geographic map engine     │
│ Supabase/Postgres        │ FOMO cloud venue master/control   │
│ Venue Intelligence       │ Venue discovery + intelligence    │
│ Country Pack Builder     │ Offline venue databases           │
│ SQLite Country Packs     │ Device venue distribution          │
│ FOMO Map Engine          │ Runtime integration               │
│ Supabase Realtime        │ Dynamic FOMO application state    │
│ FOMO Mobile App          │ User experience                    │
└──────────────────────────┴──────────────────────────────────┘
```

### Critical rule

**Do not attempt to store FOMO venue records inside Organic Maps' internal map database.**

Organic Maps provides the geographic foundation.

FOMO provides the venue intelligence layer above it.

# 5. Permanent FOMO Venue Identity

Every accepted venue receives a globally unique FOMO Venue ID.

Example:

```text
FMO-ZA-GP-JHB-00000127
```

## Permanent Identity Rules

The **FOMO Venue ID never changes.**

It survives:

* venue updates
* source changes
* provider changes
* category changes
* ownership changes
* address updates
* pack regeneration
* Country Pack versions
* database migrations
* synchronization
* mobile pack updates

### Provider IDs are reference fields only

Examples:

```text
OSM ID
Google Place ID
Foursquare ID
Other Provider IDs
```

They must **never** become the canonical FOMO identity.

```text
FOMO Venue
│
├── FOMO Venue ID
│       └── PERMANENT
│
└── External References
    ├── OSM ID
    ├── Google Place ID
    ├── Foursquare ID
    └── Other IDs
```

```text
Imported Record
      ↓

      ↓

      ↓
Exact Match?
   ┌──┴──┐
  YES    NO
   │      │
   ▼      ▼
 Merge   Candidate Matching
            ↓
       Similarity Analysis
            ↓
       Confidence Score
        ┌───┴───┐
       HIGH    LOW
        │        │
        ▼        ▼
```

Duplicate resolution must never accidentally create multiple FOMO Venue IDs for the same physical venue.

```text
       ├── Pack v3
```

# 47. Venue Closure

Never simply delete a closed venue.

Instead:

```text
ACTIVE
   ↓
TEMPORARILY_CLOSED
```

or:

```text
ACTIVE
   ↓
PERMANENTLY_CLOSED
```

Historical identity remains available.

The FOMO Venue ID remains reserved permanently.

# 53. Production Invariants

These rules are **non-negotiable**.

### Identity

```text
FOMO Venue ID never changes.
```

### Providers

```text
Provider IDs are references only.
```

### Organic Maps

```text
Never modify Organic Maps' internal geographic database
to store FOMO venue intelligence.
```

### Packs

```text
Only validated packs can be released.
```

### Media

```text
Store references in venue records.
Store actual media in object storage.
```

### Offline

```text
FOMO venue discovery must not require Supabase
once the relevant Country Pack is installed.
```

### Dynamic data

```text
Realtime FOMO state must remain separate from
the permanent venue identity layer.
```

### Updates

```text
Pack updates must be atomic.
Failed updates must preserve the previous working version.
```

### Deletion

```text
Never recycle a FOMO Venue ID.
```

### The four critical layers are now crystal clear:

**1. Organic Maps**
The offline geographic world.

**2. Global Venue Master**
The authoritative FOMO venue universe.

The optimized offline distribution of that venue universe.

**4. FOMO Map Engine**
The runtime bridge that puts FOMO's venues, categories and intelligence onto the Organic Maps geographic canvas.

That is the version I would treat as the **master specification** for the Global Venue Pack platform going forward.
